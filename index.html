Projet Tutoré de BUT

Introduction

Durant ma 3ᵉ année de BUT Informatique, nous avons commencé un projet tutoré d'environ 200 heures étalé sur l'ensemble de l'année. Avec mes 3 autres coéquipiers, notre sujet était de créer un nouveau système de caméras plus performant que les systèmes actuels, en utilisant la collaboration des utilisateurs et l'intelligence artificielle.

Nous devions donc préparer ce projet par une étude préalable et une analyse du projet. Puis commencer à développer par itération de 20 à 30 heures avec une restitution à nos tuteurs par le biais d'une présentation orale

3 services principaux

Nous avons développé 3 grandes solutions pour pouvoir avancer sur le projet :

  • Un service de calcul, celui-ci est développé en Python et il est celui dont je me suis occupé. Il s'occupe de pouvoir communiquer avec les caméras à travers la bibliothèque OpenCV en utilisant les flux RTSP. Elle s'occupe aussi de détecter s'il y a une présence humaine à travers la bibliothèque YOLO qui est une intelligence artificielle qui fait de la détection et de la classification d'images. Enfin elle permet aussi de pouvoir envoyer des notifications en cas de détection au service central, et utilise la bibliothèque Flask pour recevoir des informations du service central.

    Schéma représentant comment l'algorithme YOLO agit.

  • Une application mobile, celle-ci développée en Flutter. Elle est l'interface utilisateur, elle permet de recevoir les notifications en cas d'alerte.
  • Un service central, il est le centre de toute l'application, il communique avec la base de données, l'application mobile et les services de calcul. Celui-ci est développé en Java avec la bibliothèque Spring Boot pour en faire une API.

Un système semi-supervisé

Le but était que le système n'envoie des notifications que quand cela est nécessaire. Il fallait donc déterminer quand une situation était suspecte, nous avions d'abord pensé à l'image, mais mis à part détecter l'humain, il est impossible de définir par exemple si une personne est un cambrioleur ou non.

Nous sommes donc partis sur 3 facteurs : s'il y a un humain présent ? à quelle heure ? combien de temps ?

L'humain est détecté par l'algorithme YOLO, l'heure et le temps sont évalués avec un apprentissage qui dépend de l'utilisateur. Nous sommes donc partis sur l'utilisation du modèle Isolation Forest, intégré dans le service de calcul, qui nous permet d'enregistrer une durée en fonction de l'heure et de déterminer si la nouvelle donnée est cohérente pour pouvoir envoyer une notification.

Schéma représentant comment une situation est considérée comme suspecte.

Mobile Data Terminal

Introduction

Dans le cadre d'une communauté de jeu de rôle sur le jeu vidéo Grand Theft Auto 5, on m'avait proposé de développer ce projet, un "Mobile Data Terminal", un intranet pour les membres qui jouent des rôles de policiers, pompiers, médecins, politiques, etc. afin de mieux organiser et d'embellir leur jeu.

Les technologies utilisées sont : NextJS, TailwindCSS ainsi que PrismaDB.

Utilisation de NextJS

J'avais choisi de développer ce projet sous NextJS, qui utilise Typescript comme support ainsi que React pour le Front-End. Le système de Layout de NextJS m'a permis de m'organiser pour les thèmes graphiques/CSS (faits avec TailwindCSS) surtout avec l'utilisation de React qui permet de "fractionner le code" et pouvoir modifier chaque composant séparément permettant une meilleure lisibilité du code.

Authentification

Pour l'authentification, j'ai décidé d'utiliser NextAuth qui est un import NextJs pour gérer les credentials et les tokens. J'ai fait en sorte que la connexion ne soit disponible qu'avec discord, car dans notre contexte, cela permettait de vérifier diverses informations (si l'utilisateur est sur liste blanche, si l'utilisateur est dans l'administration du serveur, si l'utilisateur joue un personnage dans les services publics).

Base de données

J'ai décidé d'utiliser Prisma, qui est un ORM permettant de gérer les schémas de base de données de manière plus efficace. De plus, Prisma permet de convertir les enregistrements de la base de données sous forme d'objets, ce qui est un plus sur un environnement NextJS surtout que celui-ci peut être utilisé sous TypeScript. Prisma permet aussi d'intégrer le schéma de base de données sur n'importe quel type de SGBD, dans notre cas, j'avais décidé d'utiliser une base de données PostgreSQL.

Fonctionnalités

Diverses fonctionnalités ont été mises en place pour l'instant sur le MDT :

  • Multi-profil (plusieurs personnages pour un compte Discord)
  • Rôles personnalisables (Les chefs de factions peuvent créer autant de grades qu'ils veulent et leur attribuer des permissions)
  • Validation de comptes par les chefs de factions
  • Rapport sous markdown avec un système de modèles personnalisables
  • Pointeuse pour enregistrer les temps de jeu (Prendre son service/Finir son service, voir les différents services effectués)
  • Encoder un citoyen, un véhicule, une propriété, une arme ...
  • Gestion des employés (Licencier, modifier le grade, voir le nombre d'heures...)
  • Panel pour l'administration du serveur

Conclusion

Aujourd'hui, la communauté qui m'avait demandé de développer le MDT a abandonné son projet. Cependant, je continue à travailler sur ce projet pour m'améliorer avec les technologies utilisées dans cette application.
